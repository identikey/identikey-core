## Findings (nits)

1. **Nest exception is in protocol, shadowed locally.**
   Spec “Join does not Elect” accepts ops from `admin: true` on
   “the applied roster,” except outer genesis
   (`specs/guild-keyspaces/spec.md` 31–35). Protocol §6.1: inner
   genesis (`keyspace.nest`) is signed by an **outer** admin; the
   actor is `admin: true` on the applied **outer** roster, not the
   nest body’s inner roster. Do not re-specify. Do not authorize
   nest against the inner roster.

2. **No rewrap kind.** Scenario “PUK rotate then rewrap”
   (`spec.md` 82–86) allows “an epoch (or a rewrap to latest PUK).”
   Protocol bodies that carry wraps are join / nest / epoch-begin
   only (`identikey-keyspace-v1` §9). `ChangeBody` has no wraps.
   Implement wrap-list change as `keyspace.epoch-begin` then
   `epoch-commit`. Do not add `keyspace.rewrap`.

3. **“request-to-bytes” is not an identikey-keys API.** Kick
   scenario (`spec.md` 114–119) copies guardian language from
   protocol §8. This crate applies roster/blacklist immediately.
   It does not serve bytes. Runtime should deny against the applied
   roster, not invent a guardian.

## What is solid

- Send-back items actually moved: protocol is the wire; no second
  id, no eighth kind, no `guild.*`, no merge of concurrent
  `epoch-begin`; radio/Admin SHALLs are gone from this capability.
- C2 mapping is now a table: wrap-target is latest PUK; IdentiKey
  Sign+Auth is not a wrap-target and must not be on the roster;
  P-256-only members wrap-only (`design.md` 50–64). That matches
  protocol §5 and the store we have: `authorize_elect` gates the
  XID document (`crates/identikey-keys/src/privilege.rs` 101–113;
  `store.rs` 542); Sign+Auth is `IDENTIKEY_C2_PRIVILEGES`
  (`privilege.rs` 22–23); devices are `credentials` rows
  (`lib.rs` 41, 57–58); `revoke_device` only sets `revoked_at`
  (`store.rs` 487–500).
- Device cascade is protocol §2.1, not a PTK wrap-list edit.
- Fade is administering liveness (protocol §6.1), not remaining
  PTK unwraps. Hybrid eviction is instant roster/blacklist plus
  epoch. Concurrent begins: nack-or-parent; identikey-log
  surfaces concurrency and does not merge
  (`identikey-protocol` `crates/identikey-log/src/lib.rs` 76–77);
  `nacks` is a real assertion (`codec.rs` `PRED_NACKS`).
- Genesis id is identikey-log `content_hash` (blake3 of unsigned
  envelope bytes, `codec.rs` 190–202). Postgres is a cache.
- Two profiles as protocol `profile` strings. `assign-node` `node`
  is opaque 32 bytes; Lightning Mesh fills it; this crate does not
  interpret. Wrap-on-login stays `identikey-core-trr.2`.
- No OIDC `guilds` claim: ID token is iss/sub/aud/iat/exp +
  optional nonce (`crates/identikey-oidc/src/signing.rs` 111–120);
  userinfo is `{sub}` (`provider.rs` 398–403).
- Three layers uncollapsed. `managed-custody` unmodified.
  Journey is honest: no new UI.
