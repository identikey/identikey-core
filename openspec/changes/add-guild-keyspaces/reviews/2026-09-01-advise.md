## Verdict

Send-back. Steer is still the right object. The protocol landing
already named the wire facts this ADR would otherwise invent, and
the product deltas still contradict that landing plus the C2 store
we actually have. `act` would silently re-steer.

## Steelman against

Keep this packet as product-only prose: “distributed object, FOKS
methods, log is transport, two profiles.” Protocol owns kinds and
id. Mesh owns SSID. Fold later. That is how the out-of-scope list
reads.

It fails because the **deltas already SHALL** radio association,
Lightning Admin verbs, and a device-on-PTK wrap path. Those are
either false of identikey-core or they fork
`identikey-keyspace-v1`. An independent implementer of
`identikey-keys` cannot pick a keyspace id, an admin bit, or a
device cascade without reading a *different* repo’s standard that
this change does not cite.

## One real tradeoff

Cite `identikey-keyspace-v1` as the protocol source and write only
the identikey-keys mapping (C2 Elect vs PUK wrap-target, Postgres
cache, no XID rewrite) versus re-specify kinds/id/admin here and
drift. The first is the split ADR-002 already made. The second
makes ADR-012 a second standard.

## Findings

1. **Protocol already landed; this change does not cite it.**
   `docs/standards/identikey-keyspace-v1.md` (folded
   `add-keyspace-spec`, 2026-09-01) names genesis id as the
   identikey-log `content_hash` of the first admin `keyspace.join`
   (§3), roster `admin` boolean (§6), seven kinds (§4.1), wrap
   CBOR (§7), and concurrent `epoch-begin` as nack-or-parent
   (§8). This design still talks as if those are unnamed
   (`design.md` 48–50, 75–77). ADR-012 cannot invent a second
   identifier or an eighth kind.

2. **FOKS device cascade is specified wrongly for this crate.**
   Spec scenario “Device revoke cascades the wrap-list” says a
   revoked **device** drops off the **PTK** wrap-list
   (`specs/guild-keyspaces/spec.md` 33–38). Protocol §2.1 is
   device revoke → rotate PUK → rewrap PTK to latest PUK;
   device objects are not `keyspace.*`. identikey-keys devices
   are `credentials` rows, not wrap-targets
   (`crates/identikey-keys/src/lib.rs` 41, 57–58). `act` would
   have to pick which lie to implement.

3. **C2 privilege split is not mapped onto PUK.**
   `authorize_elect` gates the member XID document
   (`crates/identikey-keys/src/privilege.rs` 101–113;
   `store.rs` 542). Design says keyspace ops are signed by a
   keyspace admin, not IdentiKey Sign (`design.md` 131–132).
   It never says: wrap-target is the user’s latest PUK (Ed25519
   or P-256); C2 Sign+Auth is not a wrap-target; P-256-only
   members cannot author `keyspace.*` (protocol §5). Without
   that sentence, a C2 join looks like an Elect rewrite, which
   the same spec forbids.

4. **Radio and Lightning Admin SHALLs are in the wrong living
   spec.** “Client SSID SHALL…” and “Lightning Admin SHALL
   expose join/change…” (`specs/guild-keyspaces/spec.md` 46–50,
   110–118) are Lightning Mesh. Client SSID already lives in
   `lightning-mesh` `openspec/specs/client-network-name/spec.md`.
   Folding them here makes identikey-core claim radio behavior
   it does not implement.

5. **Fade vs remaining wraps.** “If no admin key continues, the
   keyspace SHALL fade” (`specs/guild-keyspaces/spec.md` 7–9)
   is liveness of administering (protocol §6.1). Ciphertext
   keyed to the last PTK still decrypts until epoch. The delta
   does not say that. Hybrid eviction is otherwise the right
   shape (`identikey-log` surfaces concurrency and does not
   merge: `crates/identikey-log/src/lib.rs` 76–77).

## What is solid

- Steer D1–D5 held: radio ≠ membership; distributed object;
  hybrid eviction; log is transport; protocol `keyspace`,
  product `guild`.
- Join/leave is not an Elect rewrite of the member XID. C2
  `authorize_elect` stays on the identity document.
- `consent_log` is not the keyspace log (AGPL/recrypt reason
  in `lib.rs` 53–54). Postgres is a cache.
- Three layers uncollapsed. Recrypt overlay `mjolnir-mesh-6t7`
  stays deferred. No `guild.*` ops. No OIDC `guilds` claim:
  ID token is iss/sub/aud/iat/exp + optional nonce
  (`crates/identikey-oidc/src/signing.rs` 111–120); userinfo
  is `{sub}` (`provider.rs` 398–403).
- Out-of-scope list is the right later nodes.
- Journey is honest: no new UI on this node.
