## Verdict

Act can proceed. The 2026-08-18 send-back killed the dead assumption
(“Basic OP can referee this OP”). The amendment shrinks the
instrument to Config OP only, names the plan, drops login/seed,
specifies network, and makes the red-job rule coherent with a
document this OP already serves.

Config OP-only is the right referee for this public PKCE OP. It
does not authorize, does not need confidential clients, and does
not need `/authorize/dev`. Basic OP stays out until
`client_secret_basic` / `client_secret_post` exist. That is not a
rewrite of folded `add-oidc-endpoints`.

Act does **not** invent: plan id, login, seed, image source,
network, or red-job policy. Remaining holes are mechanical (pin
digest, wire `CONFORMANCE_SERVER`, boot the binary).

## Steelman against

“Config OP only GETs JSON. `DiscoveryDocument::for_issuer` already
unit-tests the same fields. Wire Basic OP as a required red job
until confidential clients land — that *is* the instrument.”

Rejected. Unit tests do not GET the live document through HTTP
with issuer-origin matching. Config OP does. A required Basic OP
job would paint `main` red for a grant this node advertises it
does not have (`none` only). That is a broken gate, not
property-red. The prior advise already made that case; the
amendment accepted it.

**Config OP green** (can pass on today’s discovery) versus
**Basic OP** (the real code-flow referee). Config OP will not
catch a broken `/authorize` or PKCE verifier. The change says so
and parks Basic OP behind a future confidential-client change.
Weaker instrument; actually runnable. Correct.
