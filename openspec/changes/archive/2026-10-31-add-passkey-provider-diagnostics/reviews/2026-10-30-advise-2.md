## Independent take

Written before opening design.md, tasks.md, the delta, or the previous review; based on Why, the living requirement, and cited code. The supplied packet already disclosed the proposed amendment.

1. Pin actionable status separately from collapsed technical details, preserving keyboard access and announcements.
2. Pin the copied report to observed facts; an unfinished prompt cannot establish cancellation, account absence, or provider installation.
3. Pin an explicit pre-prompt failure stage for signup creation and registration renewal, both of which can fail before create.
4. Pin that same distinction for login options renewal and device assertion begin, both of which precede get.
5. Refuse to describe a failed device denial as a browser prompt or credential-verification failure: refuse invokes neither.
6. Pin the browser-call boundary separately from the later server finish request so the report identifies the failed operation.
7. Refuse raw error messages, response bodies, ceremony values, credentials, or account identifiers in a shareable diagnostic report.
8. Pin retry semantics: retain pending signup identity, renew consumed login options, and preserve the OIDC context.
9. Pin honest clipboard feedback that retains the original failure and never reports a rejected write as copied.
10. Tradeoff: a small explicit stage vocabulary loses per-endpoint detail but gives truthful support evidence without exposing sensitive request context.

## Comparison and steelman

Endpoint-specific stages, a detailed state machine, provider detection, and support submission are unnecessary to resolve R1. The existing open test obligation is implementation work, not a reason to withhold acceptance of the now-testable contract.
